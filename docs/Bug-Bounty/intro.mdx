# Start Here: The Hunter's Path

`Bug Bounty` · `Start Here` · `Level: Everyone` · `Reading time: ~8 min`

Bug bounty hunting means finding security vulnerabilities in real companies' systems — with their permission — and getting rewarded for reporting them responsibly. It is one of the few fields where a self-taught beginner and a twenty-year veteran compete on exactly the same targets, and where the only thing that counts is a **valid, well-reported bug**.

This section is built as a **path**, not a pile of links. It pulls together the methods used by working hunters, community methodology repositories, public write-ups and research, and reorganises them into one route you can follow from your first day to full-time hunting.

---

## The Five Stages

```text
Stage 1  FOUNDATIONS        Understand the game, learn the core skills, set up your tools
   │
Stage 2  RECON              Map the target: domains, endpoints, JavaScript, leaks
   │
Stage 3  HUNTING            A methodology + a Hunt Card for every bug class
   │
Stage 4  LEVEL UP           Automation, chaining, source code, CVEs, AI done right
   │
Stage 5  REPORT & CAREER    Reports that pay, triage, disputes, income, longevity
```

Each stage is a folder in the sidebar. Read in order the first time; afterwards, use it as a reference.

<Admonition type="tip" title="The honest timeline">

Most people take **months**, not weeks, to find their first valid bug — and many quit just before they would have. Expect to spend your first period mostly learning and collecting duplicates. That's normal. Consistency beats talent in this field.

</Admonition>

## The Three Rules That Never Change

<Admonition type="warning" title="Read this before anything else">

1. **Only test what's in scope.** Testing outside a program's scope — or a company without a program — can be illegal, regardless of your intentions.
2. **Follow the program's rules.** Rate limits, banned techniques (DoS, social engineering, physical), test-account requirements, and data-handling rules are part of the contract.
3. **Do no harm.** Use your own test accounts. Don't access, keep or share other people's data beyond the minimum needed to prove the issue. Stop and report as soon as impact is proven.

</Admonition>

## Your First Hour

If you're starting today:

1. Read **[What Bug Bounty Really Is](./01-Foundations/01-what-is-bug-bounty.mdx)** (15 minutes).
2. Create a free account on the **PortSwigger Web Security Academy** and solve the first access-control lab.
3. Install **Burp Suite Community** or **Caido** and proxy your browser through it (see **[Hunter Setup](./01-Foundations/04-hunter-setup.mdx)**).
4. Create accounts on one or two bug bounty platforms and *read* a few public programs' policies — don't test anything yet.
5. Read three disclosed reports on HackerOne Hacktivity for a bug class you just studied.

That's it. You've started.
